Note:

Server always replies json formated data to browser in which field 'status' must be contained to indicate
that if the previous operation is successful or not.

Valid values for field 'status' are 'success' and 'error'.

When 'error' status occurs, another filed 'errmsg' is included to points out what happened.

POST /task:

    body: {"url": "...", "ydl_opts": {"format": "..."}}

    A single video replies {"status": "success", "tid": "..."}.

    A YouTube playlist URL (youtube.com/playlist?list=..., no 'v' parameter) is
    expanded by the server into one task per video. Videos already in the task
    list are skipped:

        {"status": "success", "tids": ["...", ...], "added": N, "skipped": M}

    An empty or unreadable playlist replies 'error' with an 'errmsg'.

POST /task/batch/{pause|resume|delete}:

    body: {"tids": ["...", ...]}            for pause and resume
          {"tids": [...], "del_file": true} for delete, to also remove the files

    Each tid is processed independently. If all succeed the reply is
    {"status": "success"}; otherwise 'status' is still 'success' and 'detail'
    lists the tasks that failed:

        {"status": "success", "detail": [["<tid>", "<errmsg>"], ...]}

    A body without 'tids' replies 'error'.
